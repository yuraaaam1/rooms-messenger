# План реализации Messenger

Обновлено: 2026-10-19.

## Правила работы

- Основание разработки: утверждённое TZ.pdf и отдельно согласованные уточнения.
- Изменения требований сначала согласовываются с пользователем.
- Код предлагается небольшими шагами с объяснениями; пользователь вносит его в IDE.
- Каждый микро-шаг разбирается подробно: роль модуля, вход и выход, порядок вызовов, причины проверок и границы ответственности.
- Проверенный результат отмечается выполненным. Предложенный в чате код выполненным не считается.
- Согласованные решения фиксируются в docs/decisions.md.
- Текущее исключение docs/ и TODO.md из Git временное и оставлено по решению пользователя.

## Основание архитектуры

- Сервер: PHP, файловое JSON-хранилище без внешней СУБД.
- Клиент: статические HTML/CSS/JavaScript, Web Crypto API, без обязательной сборки.
- Получение сообщений: HTTP polling.
- Пароль комнаты: SHA-256-хеш по утверждённому ТЗ.
- Локальное хранение ключевого контейнера и истории: localStorage по ТЗ.
- ADR-001: две независимые пары P-256, ECDH для общего секрета и ECDSA для подписей.
- ADR-002: слои transport/service/repository, ручная DI и интерфейс репозитория.
- Группировка кода по фичам применяется при необходимости.
- PAKE, IndexedDB и изменение форматов API не включены в рабочий scope без отдельного согласования.

## Учёт прогресса

Оценка условная, по трудоёмкости блоков, а не по числу строк или файлов.
Проценты отражают укрупнённую оценку на 2026-10-16. Исправления HTTP-входа внесены;
ответы 415 и 400 подтверждены пользователем. Сохранение meta.json через временный
файл проверено на текущем коде в отдельном временном хранилище.
Грубые проценты не пересчитываются после каждого небольшого исправления.
Подтверждён сквозной клиентский сценарий создания, сохранения в localStorage,
перезагрузки, чтения и разблокировки ключей. За блок ключей зачтено 15 из 20
процентных пунктов: межвкладочная защита подтверждена, подключение сценария
к интерфейсу ещё не завершено. Серверная аутентификация и обмен сообщениями
пока не реализованы. Небольшие шаги интерфейса оценку пока не повышают.

### Прототип практики

Базовый демонстрационный сценарий: два независимых участника создают/находят комнату,
входят по паролю с подтверждением владения ключом и обмениваются подписанными
зашифрованными текстовыми сообщениями через HTTP polling.

| Блок | Вес | Зачтено |
|---|---:|---:|
| Основа PHP/JS, конфигурация, обработка HTTP и надёжность хранения | 15% | 10% |
| Создание комнаты, создатель и участники | 15% | 5% |
| Ключи пользователя, шифрование контейнера, создание/разблокировка | 20% | 15% |
| Вход по паролю с проверкой ECDSA-подписи | 15% | 0% |
| ECDH, HKDF, шифрование и подписи сообщений | 15% | 0% |
| Отправка, хранение ciphertext и polling | 10% | 0% |
| Интерфейс и сквозные проверки демонстрации | 10% | 0% |
| Итого | 100% | 30% |

Ориентировочно готово 30%, осталось 70%.

### Полная версия по ТЗ

Веса дополнительных блоков учитывают их интеграцию с прототипом, без повторного
учёта уже выполненных работ.

| Блок | Вес | Зачтено |
|---|---:|---:|
| Завершённый прототип практики | 30% | 9% |
| Групповые комнаты и распределение/обновление ключей | 15% | 0% |
| Администратор, пароль, блокировки и удаление комнаты | 10% | 0% |
| Фрагментированная передача файлов и очистка | 20% | 0% |
| Локальная история, экспорт и импорт backup | 10% | 0% |
| Проверки, защита, HTTPS, настройка и документация | 15% | 0% |
| Итого | 100% | 9% |

Ориентировочно готово 9%, осталось 91%.
Проценты не являются прогнозом сроков; веса пересматриваются при уточнении сложности.
